1 Description

[hide]

Repatch replaces the pixels of a hole with content synthesized from the rest of the image, in the manner of the content-aware fill and healing brush tools of raster editors. The hole is either painted directly on the image with a brush (the default), or taken from a separate mask image.

The tool works coarse-to-fine. At a very low resolution the hole is filled by smooth diffusion, which fixes the large-scale gradient and brightness. Then, at each finer level, every patch that overlaps the hole is matched to the most similar patch elsewhere in the image with the PatchMatch algorithm[1], and the hole pixels are rebuilt by averaging what those matches propose. The result carries the surrounding noise, gradient and texture into the hole.

Repatch is not magic: it can only reuse what already exists in the image. It is ideal for removing satellite trails, hot columns, blooming spikes, small artifacts, or unwanted objects on background; it cannot invent structure that the surroundings do not contain.

This release implements the classic, non-neural PatchMatch algorithm. It runs entirely on the local machine, honours the global parallelism settings, and produces byte-identical results for a given random seed regardless of the number of threads.


2 Usage

[hide]

2.1 Painting with the brush

Repatch is a dynamic tool, like CloneStamp: with its window open you paint on an image view. Mask source must be set to Brush (the default).

  1. Pick the target. Your first press-and-drag on a main view both selects that view as the session target and paints the first stroke (release without dragging to paint a single dot). The Patch, Sampling and Output parameters freeze at that moment and stay greyed out until the session ends, so set them first. The status line under the brush controls changes from No target view selected to Target: … (N stroke(s)). One session works on one view: commit it before painting elsewhere. Previews are not supported as targets, only main views.
  2. Paint. Press the left button and drag over the defect. The circle under the cursor is the brush; the orange band is the region the stroke will cover. Release the button and the region is filled immediately from the surrounding pixels. Each new stroke sees the already-filled image, so you can work outwards from a clean area.
  3. Adjust. Radius ([ / ], with Shift in steps of 10), Softness and Opacity apply to the next stroke. Undo stroke (Ctrl+Z), Redo (Ctrl+Y) and Clear restore pixels exactly; nothing is recomputed.
  4. Commit. Press the Apply button (the check mark). The whole session becomes a single Repatch entry in the view's history, with the strokes and the seed as parameters, so the history icon can be dragged onto another copy of the image and reproduces the same pixels. The Cancel button (the cross) or closing the window restores the original pixels and releases the target.

In Brush mode a Sample ring of 0 means automatic: sources come from a ring of max(32, 3 × radius) pixels around each stroke, which keeps large images responsive; enter a value to override it. Feather does not apply to brush strokes at all; each stroke's own Softness and Opacity control its edge and how much of the hole is replaced.

2.2 Working with a mask image

Set Mask source to Mask image for this workflow. It suits scripted or batch work, and masks generated with PixelMath, StarMask or a binarized copy of the image.

  1. Make a mask image with the same dimensions as the target (or as its main image, if you will run on a preview). Any pixel with a value strictly greater than Threshold (default 0.5) is filled. Grow the mask a little beyond the defect; one or two pixels of margin avoid halos.
  2. Use a preview. Define a preview around the defect and apply Repatch to it. Only the preview is processed, so iterations are fast. When the result looks right, apply the same instance to the main image; the mask is used at full size.
  3. Commit. Press Apply with the target view active. The history explorer records the instance; Undo restores.
  4. Check the console. It prints the hole size, the pyramid levels, the random seed and the time. With Random seed = 0 a new seed is drawn each run and reported; enter it to reproduce a result you like.

2.3 Mode

Patch

The PatchMatch algorithm described in this document. The only mode available in this release.

Neural

Reserved for a future neural-network (ONNX) inpainting mode. Disabled.

2.4 Mask source

Brush

The default. The region to fill is painted directly on the target view; see Painting with the brush.

Mask image

The region to fill is taken from a separate mask view; see Working with a mask image and the Mask section. Switching sources while a brush session has strokes discards them, after confirmation.

2.5 Brush

These controls are only used when Mask source is Brush.

Radius

Brush radius in pixels (1 to 500, default 15). The keys [ and ] change it by 1, or by 10 with Shift.

Softness

0 to 1, default 0.5. With 0 the whole disc is replaced with a hard edge; higher values fade the fill into the original over the outer part of the radius (1 fades over the whole radius).

Opacity

0 to 1, default 1. How much of the synthesized content is mixed into the hole of a stroke: 1 replaces the pixels, 0.5 blends half synthesized and half original. This is the brush-mode counterpart of Feather, which does not apply to strokes.

strokes

The table of committed strokes (per-point x/y coordinates plus each stroke's radius, softness and opacity), written by painting and read back on execution to replay the session exactly. It is not meant to be edited by hand, but a script can set it directly to generate brush instances.

2.6 Mask

Mask image

The view that defines the hole. Main views only. If the target is a preview and the mask has the main image's dimensions, the mask is cropped to the preview automatically. A colour mask uses its first channel.

Threshold

0 to 1, default 0.5. Mask values strictly above this are filled.

2.7 Patch

Patch size

5 to 41, odd, default 11. The side in pixels of the square patches being compared and copied; even values are rounded up. Larger patches preserve larger structures (gradients, big stars) but are slower and can look repetitive; smaller patches follow fine texture and noise. Rule of thumb: at least the size of the largest feature you want reproduced, and not larger than half the hole.

Pyramid levels / Auto

1 to 8. How many resolution levels to use. Auto picks 1 + log2(hole size / patch size), clipped so that the coarsest level is still at least two patches wide, i.e. the hole is about one patch wide at the coarsest level. Set it manually to 1 for tiny holes or when you want purely local texture; more levels give more coherent large-scale structure in big holes. Either way the number is an upper bound: levels whose sample ring or search radius leaves no room for a whole source patch at that scale are dropped, and the console reports how many were actually used.

Iterations

1 to 50, default 5. PatchMatch passes (propagation and random search) per pyramid level. Quality saturates quickly; 4 to 6 is plenty, and the running time grows roughly linearly.

2.8 Sampling

Search radius

Pixels; 0 means unbounded. Limits how far from a hole pixel its source patch may be (a square of ±radius pixels). Useful on big images to keep the search local and fast. If it is so small that some hole pixels have no valid source, the process fails with searchRadius too small.

Sample ring

Pixels; 0 means the whole image (in Brush mode, 0 means automatic; see Painting with the brush). Restricts source patches to a ring of this width around the hole, measured from the hole's edge. This is the setting that makes Repatch behave on astronomical backgrounds: with a ring of 30 to 80 pixels the fill is built only from the immediate surroundings, so the gradient and noise level match. If the ring contains stars you do not want copied, widen the mask or paint from a star-free area.

The two limits are different: the sample ring says which pixels are allowed as sources at all (distance from the hole), while the search radius says how far each individual match may be from the pixel being filled.

2.9 Output

Match space

Stretched (default) compares patches on an automatically stretched copy of the image (a median/MAD screen stretch), which is what you want for linear data: faint background structure participates in the match instead of being dominated by a few bright pixels. The filled pixels are always copied from the original data, so linear images stay linear. Linear compares raw values; use it for already stretched, non-linear images.

Feather

Pixels, 0 to 256, default 3. Width of a soft blend just outside the hole that hides the seam between synthesized and original pixels; 0 disables it. Mask image mode only: there the hole itself is always fully replaced and the feather affects the ring around it. In Brush mode the feather is ignored and each stroke's Softness and Opacity take its place.

Random seed

0 draws a fresh seed on each run (in Brush mode the seed is drawn once when the session starts and stored in the instance, so undo, redo and replay are consistent). Any other value gives a reproducible result, identical for any number of threads. Changing the seed is also a quick way to get a different variant of the same fill.

3 Tips for astronomical images

[hide]

  • Work on linear data with Stretched matching, before stretching the image.
  • Mask or paint generously: include the halo of a trail or the diffraction spikes of a removed star, not just the bright core.
  • Use a sample ring of 30 to 80 pixels on backgrounds with gradients; use the whole image for repetitive textures (a flat nebula field, for instance), where more candidates help.
  • For very large holes (hundreds of pixels), increase the patch size to 15 to 21 and let Auto choose the pyramid levels.
  • RGB images are matched as one three-channel image. For narrowband data with very different channel statistics, consider filling each channel separately.
  • The cost scales with the number of hole pixels, not with the image size; a search radius or sample ring makes large images faster still.

4 Troubleshooting

[hide]

no valid source region

At full resolution no patch fits without touching the hole: the sample ring is too narrow, the patch is too large, or the hole covers almost the whole (preview) image. Increase the ring, reduce the patch size, or use a larger preview.

searchRadius too small

Some hole pixels have no source within the search radius. Increase it or set it to 0.

Mask dimensions do not match

The mask must have the dimensions of the target, or of the main image when the target is a preview.

painting is only supported on main views

The brush cannot start a session on a preview. Zoom into the main view instead.

Visible seam

In Mask image mode increase Feather or enlarge the mask by a pixel or two; in Brush mode increase Softness.

Repetitive or blocky fill

Reduce the patch size, add pyramid levels, or widen the sample ring so that more candidates are available.

Slow

Use a preview, set a search radius or a sample ring, or reduce the iterations.

5 Algorithm summary

[hide]

For each pyramid level, from the coarsest to the finest:

  1. A nearest-neighbour field maps every patch overlapping the hole to a source patch that does not overlap it (and lies inside the sample ring and search radius, if set). At the coarsest level the hole is first filled by diffusion and the field is initialized at random; at finer levels the field is upsampled from the previous one.
  2. Iterations passes of PatchMatch improve the field: each pixel tries the offsets of its neighbours (propagation) and random offsets at decreasing distances (random search), keeping whichever gives the smallest patch distance. Distances are computed in the selected Match space.
  3. The hole is rebuilt by voting: every pixel becomes the average of the values proposed by all the source patches that cover it.

The final level writes the synthesized pixels back through the compositing weight of the hole (the brush profile and opacity, or the mask and feather). Work is split into fixed row bands with per-band random streams, which is what makes the result independent of the thread count.
